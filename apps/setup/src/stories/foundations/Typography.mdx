# Typography

SetUp's type scale, translated from the Paper exploration (`setup-product-flow`) into `src/index.css`. This page renders the live CSS custom properties — if a sample looks wrong, the token itself is wrong, not this page.

**Approved 2026-08-14**, from an exhaustive Paper audit and a cleanup pass that resolved every inconsistency it found (duplicate styles, same-role-different-values, stray one-offs). Font: the **system UI font stack** (`--font-sans`, Tailwind's built-in default — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, …`), matching Paper's "System Sans-Serif" as a deliberate choice, not a webfont. (An earlier version of this page used Geist Variable, assuming Paper's value was an unset default — that assumption was wrong; the Geist dependency has been removed.) Hierarchy is driven primarily by **size**, not by introducing new weights — SetUp uses only 300/400/500, and each token bundles its size, weight, and line-height as one unit (a real Tailwind utility, e.g. `text-body` sets all three at once — not a size-only token you pair with a separate `font-*` class). Letter-spacing is `normal` on every token; none override it.

| Token                 | Size | Weight | Line-height | Where it comes from in Paper |
| --------------------- | ---- | ------ | ------------ | ----------------------------- |
| `display-lg`          | 48px | 300    | 56px         | "102" stat (Home), hero title (Overview), hero timer (Completion) |
| `display-md`          | 32px | 300    | 40px         | Exercise titles, "Good Work!", big set-value numbers |
| `heading`              | 24px | 300    | 28px         | Section headers, "Sets" header, the live in-session counter |
| `body`                 | 16px | 400    | 24px         | The largest group — body copy, "Day N · body part" top-bars, list values |
| `body-emphasis`        | 16px | 500    | 24px         | "Hi Coral," greeting — the sole intentional emphasis moment |
| `action`               | 16px | 400    | 22px         | Button labels and stat-value chips (unified) |
| `caption`              | 14px | 400    | 20px         | "6 Exercices · 45-55 min" meta text (Home) |
| `label`                | 12px | 400    | 16px         | Field labels and Day/Set selector-chip labels (unified) |
| `label-emphasis`       | 12px | 500    | 16px         | Day-of-week letters on the weekly activity graph |

There is deliberately no separate numeric/timer/button/chip token — per the v1 rules, numeric content and component-specific text use the same hierarchy as everything else (`action` covers both button labels and stat-value chips; `heading` covers both section headers and the live timer; `display-lg` covers both the big stat number and hero timers). Don't create a `Button`/`Chip`/`Timer`-named token even if a future component seems to want its own size — ask first.

**Always pair `text-{token}` with `leading-{token}`** (e.g. `text-action leading-action`) — never `text-{token}` alone. Confirmed 2026-08-14: on form controls (`button`, `input`, etc.), Tailwind's own Preflight `font: inherit` reset wins the line-height cascade over `text-*`'s built-in `--text-*--line-height` fallback, so a bare `text-action` silently renders at the browser's inherited line-height (24px) instead of 22px. A real `leading-*` utility reliably overrides Preflight; the auto-paired one doesn't. Each of the 9 tokens above has a matching `--leading-*` value in `index.css` for exactly this reason.
